# AI Company OS Core v0.1 Freeze Audit

Last updated: 2026-07-02

## Freeze Goal

This document freezes the current milestone as **AI Company OS Core v0.1**.

The purpose of this freeze is not to add more features. It is to separate the stable system core from temporary files, legacy leftovers, and unrelated broad changes before any commit or release decision.

## Stable v0.1 Scope

The v0.1 milestone is defined by these working paths:

| Area | Keep | Reason |
|------|------|--------|
| Governance core | `backend/governance/` | Main controlled entry, classification, planning, route policy, run records |
| Mini delivery | `backend/minidelivery/` | Deterministic artifact loops and verification |
| Governance router | `backend/routers/governance_router.py` | Main execution API and artifact reading |
| Mini delivery router | `backend/routers/minidelivery_router.py` | Compatibility capability endpoint |
| Collaboration core | `backend/schemas/collaboration_plan.py`, `backend/services/collaboration_*`, `backend/routers/collaboration_router.py` | Controlled multi-agent planning and execution |
| Agent plugin core | `backend/schemas/agent_manifest.py`, `backend/schemas/agent_protocol.py`, `backend/services/agent_loader.py`, `backend/services/agent_executor.py` | Manifest registration, safe loading, unified execution |
| Agent discovery controls | `backend/services/agent_discovery.py`, agent enable/disable APIs | Local agent discovery with explicit user enablement |
| Frontend recommended pages | `frontend-new/src/pages/commander`, `marketing`, `image`, `research`, `website`, `templates`, `data`, `reports`, `agent-console`, `governance` | Recommended UI routes backed by Governance/Agent platform |
| Frontend shell | `frontend-new/src/App.tsx`, `frontend-new/src/app/routes.tsx`, `frontend-new/src/components/layout/sidebar.tsx` | Formal app navigation and legacy labeling |
| Tests | `tests/test_governance.py`, `tests/test_minidelivery.py`, `tests/test_collaboration_plan.py` | Current v0.1 safety net |
| Docs | `docs/current_project_state.md`, `docs/frontend_module_backend_matrix.md`, `docs/governance_entrypoint.md`, this audit | Operator-facing system state |

## Current Runtime Shape

```text
User
  -> frontend-new
  -> POST /governance/run
  -> classify goal
  -> build execution plan
  -> either:
       1. minidelivery artifact loop
       2. collaboration.controlled multi-agent plan
  -> write run record
  -> frontend reads artifact or collaboration result
```

Agent execution is now controlled through:

```text
Local scan
  -> manifest / CLI / HTTP / API / MCP discovery
  -> enabled_agents.json
  -> AgentExecutor
  -> Collaboration
  -> Governance
```

## Recommended Entry Points

| Use case | Recommended path |
|----------|------------------|
| General controlled task | `POST /governance/run` |
| Copy/image/research/data/website artifact | `POST /governance/run` |
| Controlled multi-agent collaboration | `POST /governance/run` with `collaboration.controlled` classification |
| Agent discovery and enablement | Agent Console / discovery APIs |
| History and artifacts | Reports page / Governance run APIs |

Direct use of Boss, Workflow, Pipeline, and old Agent run routes is not recommended for v0.1.

## Must Not Be Mixed Into v0.1 Commit Without Review

These files or groups appear to be temporary, generated, or unrelated to the stable v0.1 core. They should be reviewed before staging:

| Group | Examples | Recommendation |
|-------|----------|----------------|
| Root debug scripts | `read_code*.py`, `check_*.py`, `test_*.py`, `test_payload.json` | Do not commit unless intentionally converted into real tests |
| Prompt scratch files | `FIX_PROMPT.md`, `CLAUDE_FIX_PROMPT.md` | Keep out of release commit unless moved into docs intentionally |
| Local runtime data | `user_data/`, `.profiles/` | Usually do not commit; may contain local state |
| Learned ad-hoc skill files | `skills/learned_*.md` | Review separately; likely user-local memory artifacts |
| Evidence/debug artifacts | `evidence_gate_market_research.json`, `execplan/` | Review before commit |
| Old frontend deletions | `frontend/` deleted files | Confirm whether old frontend is intentionally removed |
| Shared component deletions | deleted `frontend-new/src/components/shared/*` | Confirm build and visual impact before committing |

## Commit Strategy

If this milestone is committed, prefer separate commits:

1. `core: add governance and minidelivery controlled loops`
2. `core: add agent manifest, loader, executor, and collaboration`
3. `frontend: connect recommended pages to governance and agent console`
4. `docs: record v0.1 architecture and route matrix`
5. `tests: add governance, minidelivery, and collaboration coverage`

Do not put temporary root scripts, local user data, or unrelated generated files into the same commit.

## Verification Checklist

Before calling v0.1 stable:

- `python -m pytest tests/test_governance.py tests/test_minidelivery.py tests/test_collaboration_plan.py -q`
- `cd frontend-new && npm run build`
- `python -c "import backend.app; print('ok')"`
- Confirm route policy reports no unprotected high-risk execution path.
- Confirm recommended pages do not call `/boss`, `/workflow`, or `/pipeline`.

## Current Recommendation

Freeze feature development here. Next work should be cleanup and staging, not new capability expansion.
