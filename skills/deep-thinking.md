# 深度思考框架

## 核心原则

> 快思考是本能，慢思考是能力。先把问题想清楚，再给答案。

## 思考工具包

### 1. 第一性原理（First Principles）

剥开表象，追问本质：
```
"What is this really about?" × 3

现象: "用户流失严重"
↓ 为什么？
→ "用户说价格太贵"
↓ 这是真正原因吗？
→ "同样的功能竞品更便宜"
↓ 本质是什么？
→ "我们的价值感没有传递到用户"
```

### 2. 多角度分析（Six Hats）

| 帽子 | 角色 | 问题 |
|------|------|------|
| ⚪ 白帽 | 事实 | 我们有什么数据？缺什么数据？ |
| 🔴 红帽 | 情感 | 直觉/感受是什么？ |
| ⚫ 黑帽 | 风险 | 最坏情况？风险点在哪？ |
| 🟡 黄帽 | 乐观 | 最好结果？机会在哪？ |
| 🟢 绿帽 | 创意 | 有什么新思路？换个角度？ |
| 🔵 蓝帽 | 过程 | 我们思考的方式对吗？ |

### 3. 假设驱动（Hypothesis-Driven）

```
1. 提出假设: "我认为 X 导致 Y"
2. 设计验证: "如果 X 是真，我们应该看到 Z"
3. 收集证据: 搜索/计算/推理
4. 判断: 证实 / 证伪 / 不确定
5. 迭代: 修正假设，重新验证
```

### 4. 反向思考（Inversion）

不问你想要什么，问你想避免什么：
- "怎么做会失败？" → 反向推导出成功条件
- "最大的误解是什么？" → 消除认知盲区
- "如果我在骗自己，我会说什么？" → 识别自欺

### 5. 思维链（Chain of Thought）

复杂问题分步推理：
```
问题: [复杂问题]

Step 1: 拆解 — 这个问题包含哪几个子问题？
Step 2: 分析 — 每个子问题的事实和约束
Step 3: 关联 — 子问题之间的交互关系
Step 4: 综合 — 整体结论和不确定性
Step 5: 验证 — 我的推理有没有逻辑漏洞？
```

## 回答前的检查清单

在给出答案前：

- [ ] 我是否理解了问题的真正意图？
- [ ] 我的回答有没有逻辑漏洞（自相矛盾/循环论证）？
- [ ] 我是否区分了"事实"和"观点"？
- [ ] 我不确定的结论有没有标注？
- [ ] 是否考虑了反对意见？
- [ ] 是否给出了可操作的建议而非空话？
- [ ] 是否避免了过度简化复杂问题？

## 适用场景

| 场景 | 推荐框架 |
|------|----------|
| 商业决策 | 六顶思考帽 + 反向思考 |
| 技术选型 | 第一性原理 + 假设驱动 |
| 产品设计 | 第一性原理 + 多角度分析 |
| 解决问题 | 思维链 + 假设驱动 |
| 辩论/论证 | 反向思考 + 多角度分析 |
| 学习新领域 | 第一性原理 + 思维链 |

## 对本地 LLM 的特别提示

> 你的知识有截止日期。当需要"思考"涉及最新事实的问题时：
> 1. 先启动联网搜索获取最新信息
> 2. 再用本框架分析
> 3. 区分"基于已知知识的推理"和"基于搜索结果的推理"
> 4. 标注任何不确定的假设
